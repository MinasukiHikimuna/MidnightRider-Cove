# Data Quality

Data Quality adds a dedicated Cove page for saved video, audio, performer occurrence, and tag reviews. Enable it in **Settings → My → Interface → Navigation**.

**Requires Cove 1.5.1 or later** (`minCoveVersion`), the latest Cove release. Its extension runtime exports everything the page imports: the last exports to arrive were Cove's audio player, audio filter criteria and audio sort options (in 1.4.2-dev.184, first released in v1.5.0), together with the audio filtering and bulk custom-field support that audio reviews rely on. The page imports Cove's shared components as one module, so on an older Cove a single missing export stops the whole page from loading. Everything else it takes from Cove's extension runtime (the other shared components and the props it passes them, the keyboard dispatcher and the icons) is older.

**Known limitation until the floor is raised:** performer occurrence conditions that use None or Any in Cove's own **Performer Occurrence Tags** criterion (the toolbar's **Filters**) need Cove 1.5.2-dev.44 or later for correct totals. That criterion honours None and Any only from that development build of Cove's main branch (commit 29e83f7, merged with pull request #752 as 6045deb); no release has it yet. On an older Cove it filters nothing with them, so the queue lists every video or audio and counts them all. An occurrence review's own condition is not affected, **Has no occurrence tags** included: the page sends it inside Cove's performer filter, which honours None and Any in every Cove this version runs on.

The page opens on the reviews list: a table of the reviews with each one's kind (its icon and **Type**), name and description, and how many items it matches, counted review by review as the list opens (**…** while counting, **—** when a count fails). **Sort by** **Name** or **Matching items**, ascending or descending (by count, reviews still counting come last); this browser remembers the choice. A review's name opens it (a Ctrl-click opens it in a new tab), and its row menu offers **Edit** (opens it with the editor drawer), **Duplicate** (saves a copy named "<name> copy", or "copy 2" and so on when that name is taken, a copy of "X copy" being "X copy 2", and opens it with the editor drawer to rename it), **Export** and **Delete…**, which asks on the page before deleting. A review opened from the list gets a browser history entry of its own, so the browser's **Back** returns to the list with that review's row focused; **All reviews** goes back to the list the same way, focusing its heading. The page header offers **Import**, **Export all** and **New review**. Export writes a review file, a JSON array of saved reviews; **Import** adds the reviews of such a file that the list does not hold yet, keeps the listed ones as they are (the same review id), and says what it did, so importing a deleted review's file brings it back. The line above the table says how many reviews there are and where they are kept: your account, your account read-only (without saved-filter write permission nothing can be created, imported, edited, duplicated or deleted, while both exports stay), or this browser only. The page's storage, recovery and progress notices sit under the header.

Single-item reviews (videos, audios and performer occurrences) fill the window below Cove's navbar, so the page itself does not scroll: the queue and the item column scroll on their own, and a window too short for the workspace scrolls it under the header. One header row holds the way back, the review's name (its description shows on hover), **Edit review**, Cove's list toolbar (range, a **‹ page / pages ›** pager whose number opens a go-to field, search, sort, **Filters** and page size), then **Scope** and **Batch…** in occurrence reviews, **Single** | **Grid** in video reviews, and a **More** menu with **Edit review**, **Duplicate**, **Export**, **Delete…** and **All reviews**. Filter chips, the chosen performer, and **Queue differs from the saved review** with **Save to review** and **Reset** sit on a second row. The queue runs down the left in compact rows, the player takes the space left above the action pad, and the right column shows who or what is reviewed, the other matching partners in the scene, the current tags, the chosen performer's existing answers, **Edit tags** and **Skip**. Tags there look and sort as on Cove's video page: Cove's tag badges, coloured by the tag or its group and marked with the group's dot, grouped tags first by the group's order, then by name; they do not navigate away. Between about 1400 and 1700 px wide the right column narrows so the pad keeps more width; below about 1400 px it becomes a band under the pad; below 900 px everything stacks, with the queue last, and the page scrolls. **Scope** summarises who is reviewed and which occurrences, and opens the performer scope (**All performers**, **Specific performers**, **Matching criteria** with **Edit criteria**), the occurrence-tag condition and its tags, **Include subtags** and **Hide occurrences confirmed absent**; changes apply to the queue at once. Occurrence actions affect only the active performer in that video. Matching partners are reviewed together; switching partners preserves playback and clip boundaries. Video actions affect the video itself. Existing multi-tag actions, explicit absence tags, and legacy occurrence tag-choice reviews remain supported.

Audio reviews and audio performer-occurrence reviews work the same way, on Cove’s audio player. Audios have no card grid, so both run one audio at a time: there is no **Grid** layout, no card details or tag bins, and no **Select every card when a page opens**. Because an audio shows nothing while it plays, its **description** sits directly under the player in both audio review kinds, with a **Description** control that collapses it; that collapsed choice is remembered per browser and is not part of the saved review. Audio occurrence actions, assessments, **Batch…** and undo behave exactly as the video ones do, writing to the audio and to its performer occurrences. Audio reviews need **audios.write**; occurrence tagging needs **tags.write**. The first occurrence assessment on an audio offers to add audios to the existing `confirmed_absent_occurrence_tags` custom field, extending it rather than replacing the video values.

Normal video reviews also offer a card grid: **Single** | **Grid** in the review header switches the current visit either way. A temporary search, filters or tag bins come along and still show as differing from the saved review, and saving the review keeps the visit in its layout unless the review's own layout changes. The grid fits the window like the single-item workspace: the same header row (with the queue's one **‹ page / pages ›** pager in Cove's toolbar, **Single** | **Grid**, **Cards** | **Wall**, the card size and **More**) and chip row stay in place, the cards scroll on their own, and an action bar floats over their bottom edge. The bar names what the actions apply to (**N selected**, or else the focused card), offers **Select all** (**Ctrl+A**, **⌘A** on a Mac) and **Clear** (**Esc**), then a compact tile per action with a key (key cap and label; pointing at or focusing a tile shows what it changes just above the bar), one line per keyboard row that holds actions (**q…å**, **a…ä**, **z…b**) in key order, and **Find action**, which also counts and reaches the actions without a key; a line too long for the bar wraps, and the tiles move under the summary when that takes fewer rows, or as many while it keeps every keyboard row on one line. **Ctrl+A** toggles: with every card on the page selected it clears the selection; text fields keep Ctrl+A for their own text. The checkmark on each card is the selection state and stays visible in every view; the accent ring only marks the focused card. The arrow keys move between cards, **Space** selects the focused one and **Enter** previews it. Action keys work wherever focus is, including the cards, the pager and the bar; **Esc** clears the selection from the page body, the cards and the extension's own controls, while the host toolbar and dialogs keep their own Escape. A key whose action cannot run says why, just above the bar. Below 1600 px the grid's range text gives way to the pager so the header stays one row. The preview plays the card's video in a dialog over the grid: its header steps to the previous or next card (**N** / **M**), says what the actions apply to, and offers **Selected**, the video in a new tab and **Close**; a hint line lists its keys (**Space** play/pause, **←**/**→** ±60 s, **Alt** ±10 s, **Shift** ±5 s, **,**/**.** ±10 %, **↑**/**↓** volume, **Enter** or **Esc** closes), and the same action bar sits at its foot. Cove's own menus, hints and notices, such as the player's **Playback options** in a narrow window, open over the preview. After a mouse click on one of its buttons focus returns to the preview, and a button disabled by a running action or the last video hands focus back to it too, so its keys keep working; a button pressed from the keyboard keeps focus. **Edit review → Appearance → Layout** saves the layout the review opens in, and **Select every card when a page opens** (also offered for tag reviews) starts every page with all cards selected so a quick review can confirm the whole page at once. Applying an action to the whole page brings the next page in selected too, while a hand-trimmed selection stays trimmed after the refresh. Reviews that start from the end keep moving towards the first page: once a page's own cards are answered, the queue continues head-ward even when items from the pages already reviewed have shifted into it, so a deliberately skipped tail accumulates behind the cursor instead of pulling it back. Existing rules keep single-video review until a different preference is saved; occurrence reviews retain their performer-specific workspace.

Under **Appearance → Grid**, tick **Tags** in **Card details** and choose parent tags in **Tags on cards**. Each video card displays only its assigned descendant tags under those parents, excluding the parents themselves. This explicit setting is independent of the queue filters. **Queue tag bins** separately offers, in the grid's chip row under **On this page**, a toggle chip per descendant tag found on the loaded page with its page count: a pressed chip narrows the queue to that tag from the first page, and pressing it again lifts the narrowing (back at the saved queue, the queue starts where the review starts).

The URL owns the complete effective query: search, scene filters, performer scope and occurrence conditions, sorting, page size, page, and traversal direction. Bare review links load saved defaults and serialize them. Query-bearing links remain independent of subsequent default changes, including explicit empty filters. These changes replace the review's browser history entry rather than add entries; only opening a review from the list adds one. Changing any queue criteria, the occurrence scope and queue tag bins included, shows **Queue differs from the saved review** with **Save to review** and **Reset** on the header's chip row, in the single-item workspace, the card grid and tag reviews alike, and after switching between **Single** and **Grid**. Queue tag bins only narrow the visit: no save keeps them, so with nothing but bins pressed the note offers **Reset** alone, and pressed bins stay pressed after a save. **Edit review** remains the path for changing the complete rule. Opening another review starts with its defaults. New reviews start from the end; existing direction settings and explicit URL pages are honored.

**Edit review** opens the review's editor as a drawer over the right-hand column, in the single-item workspace and the card grid alike (**Edit review** in the **More** menu, and **Edit** in the review's row menu on the reviews list, open it too). The header's toolbar, **Scope**, the chip row and the queue stay live beside it as the draft's preview, and **Save review** keeps their criteria with the draft; meanwhile the review's actions, their keys and **Batch…** pause. **Review** holds the name, description, **Review direction** and, in occurrence reviews, **Performer flags**; **Appearance** (video and tag reviews) the layout the review opens in and the card grid's settings; **Actions** the actions as compact rows in review order, each with its key, which opens the key picker (see **Action keys**), one open at a time for its label and ordered steps, with **Add action**, **Add from parent tags…**, **Find an action**, duplicate, delete, and reordering by dragging or **Alt**+**↑**/**↓**; legacy occurrence reviews keep **Tag choices**. Unsaved changes are measured against the saved review: queue criteria changed before the drawer opened count from the start (**Unsaved changes, including the queue's criteria**), so **Save review** keeps them, while **Cancel** leaves them unsaved; tag bins never count. **Cancel** restores the view from before editing, and a failed save keeps the draft open. **Cancel**, **Esc** and the drawer's close button close it at once while nothing differs; with unsaved changes they first ask **Discard unsaved changes?**, where **Keep editing** returns to the drawer and **Discard** closes it, restoring the view from before editing. The browser's **Back** does not ask: it leaves the review, and its unsaved changes, for the list. The drawer is 720 px wide, 600 px in windows between about 1400 and 1700 px wide, where the review beside it has less room. **New review** on the reviews list asks in a dialog for the kind, name and description first; **Create & configure** saves the review and opens it with the drawer, and a draft that cannot be saved stays open with **Export draft**. **Duplicate** (a row's menu, or **More** in an open review) asks nothing: it saves the copy at once and opens it with the drawer.

Actions apply and advance by default. After a writing action that advances (a key, a tile, **Find action** or **Save & next**) the next video or audio starts playing, whether or not the current one was playing (moving on to another performer in the same video leaves the player as it is); **Skip**, applying and staying, and choosing an item from the queue do not start playback. Shift-click or Shift plus the action's key applies and stays; a writing action's tile also shows **Apply and stay** as a small pin tab on its top edge while pointed at or focused (**Tab** reaches it after the tile), clear of the key cap, the label and the "absent" marker. Pointing at or focusing an action previews it: the line above the pad says what it adds and removes (a tree removal that keeps the tag the action adds reads "− rest of" the parent), and the current tags show additions with "+" and a dashed outline, removals with "−" and struck through, and new absences marked "absent", around the same badges; an action that would change nothing on the item says "already so here". **Edit tags** uses Cove's shared tag selector for arbitrary additions and removals. **Save** stays, **Save & next** advances, and **Cancel** discards the local draft.

**Action keys.** A review's actions sit on the letter keys **q w e r t y u i o p å**, **a s d f g h j k l ö ä** and **z x c v b**, 27 keys that all work without AltGr on a Finnish or Swedish keyboard; **n** and **m** are never used, because the grid preview steps through videos with them. Each action is pinned to a key of its own choosing, left to **Auto** (the default) or set to **No key**: pinned actions take their keys first, then Auto actions, in review order, take the free keys in the order above, and actions with no key, or Auto actions past the last free key, are applied through **Find action**. So a review can put its first actions on the top row and a pair of them alone on **a** and **s**, with empty keys between. In **Edit review → Actions** an action's key opens the key picker, a small keyboard map where each key shows the action that holds it (a pin marks a pinned one) or nothing: choosing a key pins the action there, and the action that held that key takes this one's pinned key, a swap, or turns Auto when this one had no pin, so Auto actions may shift; **Auto** and **No key** are the other choices. The picker works from the keyboard too (arrow keys, **Enter**, **Esc**), and focus returns to the key. A copy of a pinned action starts on Auto (a copy of an action without a key stays without), and actions added from parent tags start on Auto. A key pinned twice, as an imported or hand-edited review may have, stays with the first action, and the editor says so on the later one, which takes a free key until a key is chosen for it. The review file keeps each choice in the action's `shortcut` field (a key, `none`, or nothing for Auto; the digits older versions saved read as Auto). A key applies its action and moves on, in the single-item workspace, the grid and the grid preview alike; in the single-item workspace **Shift** plus the key applies it and stays on the item, while in the grid and its preview an action always moves on, as before. **-** opens **Find action** (held down, once, without typing into its search), which lists every action, those with a key in key order and then the others, with its key and what it changes: type part of a name to narrow the list, choose with **↑**/**↓**, **Enter** applies and moves on, **Shift+Enter** applies and stays (single-item workspace), **Esc** closes. The **Find action** button opens it with the mouse. In the single-item workspace the actions sit on a pad shaped like the keyboard: each action on its key's place, in rows **q…å**, **a…ä** and **z…b** followed by **n m , .** and the **-** tile, which counts the actions only Find action reaches; rows without actions are left out, and without a bottom row **Find action** sits in the pad's header. Empty keys are dimmed and all look alike (with a video, **m** still says that Cove mutes on it). While the drawer is open, the paused pad shows the draft's placement as it changes. The keys are fixed: they work the same under every Cove keyboard preset (Cove Native, Stash or a personal one), and because they do not follow a preset, Cove's **?** overview and **Settings → Keyboard shortcuts** do not list them and they cannot be rebound there. Holding a key down applies its action once. On the Data Quality page an action key takes precedence over Cove's own use of the same key, and **f**, **g** and **k** always belong to the review in the single-item workspace and the grid, whenever the page takes keys: they apply the action placed on them and otherwise do nothing, so Cove's Filters and fullscreen on **f**, its **g** go-to chords and play/pause on **k** never fire there (**Space**, the **Filters** button and the player's fullscreen button still work). The grid preview holds Cove's keys back anyway. Keys keep working after clicking a queue item, an action button or a preview control, and never fire while typing in a text field, while tags or the review are being edited, or while a dialog other than the grid preview is open.

**Phone-sized windows.** Up to 760 px wide (phones; wider windows, desktop ones and most tablets, keep everything above), a keyboard-shaped layout makes no sense, so the single-item pad, the grid's action bar and the preview's bar show the actions as a plain grid of buttons: in key order, without key caps, empty keys or row offsets, with a little more room between the groups of the keyboard rows that hold actions, so a pinned grouping still reads. Labels get up to three lines, and the buttons are at least 44 px tall. **Find** closes the last group (with how many actions only it reaches), and key hints go: Find lists no keys, the bar drops its key hints and the key caps of **Select all** and **Clear**, and the preview drops the caps on its step buttons and its key line and puts its title on a line of its own. The bars' buttons scroll within about a third of the window's height, so the cards or the preview's player keep room (little on a phone held sideways). Touch has neither Shift nor the pin tab, so the single-item pad adds a **Stay on this item** switch: while it is on, a tapped action, on the pad or in **Find**, applies and stays on the item (an action without steps still moves on). The switch lasts from review to review until the page reloads and is never stored; the keys keep their meaning, and wider windows ignore it. The grid and its preview have no switch, as their actions always move on.

**Edit review → Actions → Add from parent tags…** builds actions from a tag hierarchy. Choose one or more parent tags and tick their direct children, listed most used first: video and audio reviews count the media tagged with each child, and occurrence reviews count the media where a performer's appearance carries it. Children that an action already adds start unticked, and a child of several chosen parents is listed once, under the first, noting the others. Actions can be added once every chosen parent has loaded. Each ticked child becomes an ordinary action named after the tag and added after the existing actions, ready to reorder, rename, extend, or delete; nothing stays linked to the parent, and running it again pre-ticks only the children no action adds yet. **Only one per video** (**per audio**, or **per performer** in occurrence reviews) makes the actions for that parent's children also remove the parent's tree: the parent and every tag under it except the one the action adds. A **Remove tags and descendants** step never removes a tag its own action adds or marks present, so such an action leaves its tag as the only one in that tree in either step order, without deleting and re-adding a tag that is already there; a batch applies the rule to each chosen answer.

In single-video and occurrence reviews, **Skip** only moves the cursor. Eligibility comes from current filters, without reviewed/inconclusive states or persistent position. Successful tag saves refresh queue membership and counts. Occurrences that no longer match the filters leave the queue; a scene leaves after its last matching performer is tagged. Skipped and still-matching items are available again when their page is revisited. These workspaces leave legacy progress untouched; multiple-video reviews retain the card selection, view preference, and progress workflow.

**Occurrence assessments** let an occurrence action mark a tag present, mark it absent, or clear the absence for the active performer. Absences are stored on the video in the `confirmed_absent_occurrence_tags` custom field as `<performerId>:<tagId>` text values, created by the setup prompt on reviews that use an assessment step. A "Has none of the selected tags" queue hides occurrences confirmed absent for every condition tag, and a "Missing at least one selected tag" queue hides an occurrence once every condition tag it misses is confirmed absent, unless **Hide occurrences confirmed absent** is switched off; with one target performer and one condition tag Cove filters them out itself, otherwise they are hidden in the browser. Name the same tags in the assessment step as in the condition: absences match exact tag ids. Batches do not offer assessment actions.

**Batch…** in an occurrence review's header opens **Apply to all matching occurrences**, which runs one or more configured occurrence-tag actions across every page of the current search, scene filters, performer scope, and occurrence conditions, honoring the review's Include subtags setting. It works in three steps shown at its top. Its tag badges show no image preview on hover: the dialog is modal and would cover the preview. **Answers**: tick the answers to apply, each shown with its key and effect; they run together, in review order, with one preview, one run, and one undo, and every batch starts with none ticked. The step also shows who and which occurrences the batch uses, the chosen performer's existing answers with a **Mixed** badge on categories holding different answers, and the flag warning for a flagged performer. **Preview all matches** moves to **Preview**, which reads every matching occurrence before anything is written: the answers to apply (**Change** returns to them), counts of matching occurrences and scenes, occurrences that will change, occurrences already correct, and occurrences with a different answer, each count listing its occurrences with links when selected, the date range with links to the earliest and latest item (in a flagged performer's warning too), and the tag changes. A different answer is a tag the chosen answers would remove: **Keep their answer** (the default) skips those occurrences, **Replace it** applies the answers there too. Configure opposite answers as removals in the action; the extension does not infer opposites. When the condition looks for missing tags ("Has none of the selected tags" or "Missing at least one selected tag") and includes subtags, each condition tag with its subtags is also a category: a batch adds an answer only where that category is still empty and keeps a different existing answer unless you choose to replace it; two answers for the same category are refused, and the preview's main button then reads **Change answers** and returns to them. To include already answered appearances, remove filters that exclude them.

**Apply to N occurrences** moves to **Run**. Batch targets and action trees are frozen before writes, with up to five occurrences processed concurrently, and a progress bar counts the processed occurrences (the whole batch for a run, its own occurrences for a retry or an undo). Cancel stops scheduling and lets in-flight writes settle. Results distinguish changed, unchanged, skipped, failed, and remaining occurrences, with the reasons for skips and failures and **Show them** for each; selecting a count lists those occurrences. **Continue** processes remaining items; **Retry failed** processes failures whose previous outcome can be verified. Affected tags changed since preview are skipped. Inspect failures with unknown write outcomes before creating a new preview. **Undo batch** reverses recorded changes while preserving unrelated edits, says how many it restored, and reports conflicts. Keep the page open during execution. Results and undo last while the dialog stays open: closing it or choosing **New batch** discards them at once, and a new batch starts with no answers selected. Closing after a write refreshes the queue and the performer ranking. No future-import defaults or background jobs are created.

Occurrence reviews add a **Scenes** | **Performers** switch above the queue (**Audios** | **Performers** in audio reviews). **Performers** lists the performers in the review's performer scope with the most matching items first, counted with the current search, scene filters, and occurrence condition. Performers are counted in order of their total items, and counting stops once nobody left can reach the places shown, so the first 50 are exact without counting every performer; only when fewer performers than that have matches is everyone with any item counted. **Show more performers** extends the list. Choose a performer to review only them: the queue and batches narrow to that performer, the URL records the choice as `performer`, a chip under the header names them, and its **Show all performers** returns to the scope. The choice is never saved into the review, and changing who is reviewed drops it. While a performer is chosen, **Existing answers** in the item column summarizes the answers they already have across all their items, per condition category, and marks a category holding different answers. Saving an occurrence recounts its performer; a batch recounts the chosen performer, or without one ranks again when the list is next shown. **Performer flags** in **Edit review → Review** names profile tags, for example ones noting that something changed during a career. A flagged performer carries a flag in the list, on the chosen performer's chip and in the item column, and while that performer is chosen the batch dialog asks to check the earliest and latest items or narrow the batch by date before applying it to all of them.

Tag-group reviews use the same grid: the review header with **Cards** | **List**, and the action bar, which names **the focused tag** when nothing is selected; **Enter** opens the focused tag in a new tab. They keep their selection and progress workflow. Review definitions use Cove's account-scoped saved-filter API with browser recovery support. See the [user guide](docs/video-data-quality.md), [interaction contract](docs/data-quality-review-interaction.md), and [storage contract](docs/storage-and-verification.md).

Registry publication remains deferred. Visual-similarity search is not available through the public extension API. No new backend endpoint or database migration is required by this workflow.
