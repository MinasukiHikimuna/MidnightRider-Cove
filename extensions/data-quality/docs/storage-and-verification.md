# Storage and verification boundaries

Configuration version 2 is stored in the current account's saved filters under `ext:com.midnightrider.data-quality:configuration`. The canonical record is named `Data Quality configuration`. It contains complete reviews, their unchanged review/action IDs, a revision token, imported-ID history, and deletion tombstones. Progress version 1 uses `ext:com.midnightrider.data-quality:progress`, one record per review. The extension never bypasses Cove authentication or authorization.

The newest existing account-scoped browser snapshot is authoritative during initial prototype adoption, including an empty array. Older snapshots supply migration history, not deleted reviews. Account-imported reviews are adopted once. Tombstones prevent a later browser from reviving deleted imports. The unscoped `page-videos` key and its import/deletion history have no trustworthy owner: they are never automatically copied to an account. The review page offers an explicit recovery export for manual import into the intended account. Original prototype keys remain untouched for recovery; the extension no longer writes them. Differing local/account edits with the same ID stop migration without overwriting either version and expose an account-scoped browser recovery download. Nonconflicting browser-only reviews can migrate when storage permissions are granted. Unknown versions and malformed data are retained and reported, not reset.

Initial loads share a single in-flight request. Identical duplicate first-install records are preserved under recovery names, with the lowest record ID retained as canonical. Conflicting duplicate account records require explicit reconciliation; the extension never picks one silently. Configuration saves are serialized within the browser and compare the remote revision before writing. A stale draft stays open and can be exported. Cove does not expose conditional writes or transactions through this API: two browsers writing at precisely the same time may still overwrite one another after both revision checks pass. Avoid concurrent editing; reload to receive another browser's saved configuration. This is a documented public-API boundary, not an atomicity guarantee.

Progress saves contain queue signature, normalized page and page size, focused video ID and its index, current view, and card width. The browser cache updates after settled navigation; account writes follow a 600 ms debounce. Sync failures keep browser caching active and offer retry. Closing a browser before account synchronization finishes can leave the other browser at its previous checkpoint. Progress does not restore selection or reopen the player. Temporary queue adjustments do not overwrite saved-queue progress.

Resume first checks the saved queue signature. Changed filters, search, sort, or page size restart at page one. An unchanged queue resumes its saved page, clamped to the new last page, and focuses the saved video if it is on that page; otherwise it uses the saved index, clamped to available results. It does not scan an entire library to locate an item that moved to another page. Empty results clear focus. A newer local checkpoint can recover an unsynchronized session. Concurrent reviewers use the latest successful progress write; progress is a checkpoint, not a review-completion ledger.

Account storage needs `savedfilters.read` and `savedfilters.write`. Read without write exposes configuration read-only; temporary filters remain usable. Without read permission, configuration and progress remain browser-only and the UI states that limitation. Video actions need `videos.write`; preview/query access continues to use Cove's existing permissions. Tag bins, annotation hierarchies, and descendant removal also need tag read access. Tag assessments additionally need `system.read` to inspect custom-field definitions. The explicit setup action requests the key `confirmed_absent_tags` through the existing custom-field creation endpoint and therefore needs `system.settings.write`. A compatible existing definition is reused; a missing definition blocks assessments until setup succeeds, while an incompatible definition must be corrected in Cove settings.

Hierarchy failures are reported, and every descendant action step in an assessment action resolves before any video write. Legacy-only actions retain one authorized bulk request per step. Assessment targets run sequentially: each target is read immediately before computing its final exact tag IDs and complete custom-field dictionary, unchanged targets are skipped, and changed targets receive at most one update request. A failed read or ambiguous update stops the remaining targets without rollback or automatic retry and reports the completed count and affected video. Other writers can still race between the read and update, and the public API has no transaction, compare-and-swap token, or field-specific mutation endpoint. Cove caches identical filtered queries for one second and exposes no public invalidation hook, so metadata actions remain pending for approximately 1.1 seconds before refreshing membership after either success or partial failure. Skip does not wait.

Queues request at most 100 videos per page and abort superseded requests. Wall previews load near the viewport and play only while visible. Bins enumerate descendant tags present on the loaded page; their counts are page counts, not library-wide aggregates. A bin adds a temporary AND condition while retaining existing filters. Card annotations support date, studio, performers, and tags, optionally restricted to descendants of configured parents.

The production UI and package must be rebuilt after changing source. Verification uses the extension's Vitest suite, its Release solution build and focused C# manifest test, Cove's production UI build, the development package validator, installation through `cove-install-extension`, and live UI workflows. Culture staging is the populated workflow reference; task-local Culture exposes the editor but its backing Stash result calls failed during this task. Neither observation is substituted for the other.

## Verified delivery

The final automated UI suite passes 45 tests across five files. The extension production UI build and Release solution build pass; the focused Release C# manifest test discovers and passes one test. Cove’s production UI build passes with its large-chunk warning. The development ZIP is extracted and checked by the package validator, and its JavaScript/CSS are compared byte-for-byte with the current build before installation. Independent code review found and resolved migration, account isolation, asynchronous loading/import, shortcut, recovery, and progress-sync issues.
