# Data Quality review interaction contract

## Video and performer occurrence reviews

The workspace fills the window below Cove's navbar; only the queue list and the item column scroll, and a window too short for the workspace scrolls it under the header instead of shrinking the player further. The player takes the space above the action pad, 16:9 and as large as fits. The item column on the right shows the active performer or media, the other matching partners in the scene, the current tags and, with a performer focus, existing answers, with **Edit tags** and **Skip** at its foot. Tags there are Cove's tag badges without navigation, in Cove's display order (OrderForDisplay: grouped tags first, then group sort order with none last, group name, sort name or name in natural order, id); existing answers keep most frequent first, ties in that order. Tags the item carries keep Cove's full tag data, and the page's shared tag cache remembers it, so previewed additions, confirmed absences and existing answers show the same badges. Cove's tag endpoint sends neither a group's sort order nor the tag's image flag, so a tag read there keeps what an item told about it and borrows its group's order from tags seen on items; until one is seen, that group sorts as one without an order. Between about 1400 and 1700 px the item column narrows (272 px); below about 1400 px it moves under the pad; below 900 px everything stacks, with queue navigation below, and the page scrolls. The queue has independent scrolling and does not depend on space left beneath the player. Current tags and the active performer are prominent. Occurrence tagging applies to this performer in this video; video tagging applies to the video. Matching partners are processed together, without remounting the player or changing clip boundaries.

Configured actions run their ordered tag steps, including multiple observations or explicit absence tags, and move on at once rather than after confirmed success: the workspace moves to the next loaded item while the write runs, and the grid takes the targeted cards off the page and focuses the next one. A write that fails puts things back and says why: the workspace returns to the item with its inputs kept and its player paused and re-reads its tags, and the grid restores the cards, their selection (unless it changed meanwhile) and the focus. In the workspace, after a writing action that moves on (a key, a tile, Find action or **Save & next**) the next video or audio starts playing whether or not the current one was playing, while moving on to another matching performer in the same video keeps the player as it is; **Skip**, apply and stay, and choosing an item in the queue do not start playback. A removal of tags and descendants never removes a tag the same action adds or marks present, so an action that adds a tag and removes its parent's tree leaves that tag as the parent's only one in either step order, without deleting and re-adding a tag already there; a tree left with nothing to remove writes nothing. Shift-click, Shift plus the action key, and the tile's **Apply and stay** pin save without advancement. The pin is a small tab on the tile's top edge, shown while the tile is pointed at or focused and reached with Tab after it; it sits in the gap above the tile and the tile's top padding, so it never covers the key cap, the label or the "absent" marker, and a click on the tile's face never lands on it. Action keys ignore key repeat and follow the rules under Keys. No advance-behavior preference is stored.

The action pad places each action on its key and labels it with that key, with empty keys between placed actions; rows without actions are omitted, and empty keys are dimmed and all look alike (f, g and k included: they do nothing on review pages, see Keys; with a video, the fixed m still says Cove mutes on it). Hovering or focusing a tile previews the action: the pad's header line summarises it, and the current tags show what it would add, remove and record as absent. The preview mirrors execution: tree removals resolve to the tree minus the tags the action adds or marks present, plain steps run before assessments, MARK_PRESENT adds and clears the absence, MARK_ABSENT removes and records it, and CLEAR_ABSENCE changes only the absence. Each tree is resolved once per review; until it is, only its parent counts as removed.

**Edit tags** creates a local draft using the shared Cove tag selector. Arbitrary additions and removals do not change the review definition. **Save** stays on the item; **Save & next** advances; **Cancel** discards the draft and returns focus to Edit tags. Duplicate submissions and competing navigation are disabled while saving. A partial failure retains the item and inputs, refreshes actual tag state, and does not report full success. A confirmed save followed by failed queue navigation is identified separately.

## Keys

Action keys, Find action and grid select-all are fixed keys, independent of Cove's keyboard presets. While mounted, the page registers them with Cove's dispatcher through `useKeySequence` bindings without an action id, which Cove matches against the keys given instead of the active preset: each action's key and Shift plus the key, `-` for Find action, and `Ctrl+a` for select-all (Cove reads ⌘ as Ctrl). Which key an action has comes from one function (`actionKeyMap`) that the pad, the action bar, Find action, the batch answers, the key registration and the editor all use: actions pinned to a key take it first (when two are pinned to the same key, the first keeps it and the later ones act as Auto), then Auto actions, in review order, take the free keys in the order q w e r t y u i o p å a s d f g h j k l ö ä z x c v b (never n or m), and actions set to no key, or Auto actions past the last free key, have none and are reached with Find action. The extension manifest declares no keyboard actions, so Cove's `?` overview and Settings → Keyboard shortcuts do not list these keys and they cannot be rebound. The single-item workspace and the grid register them on Cove's `local` surface, which outranks Cove's list, player and global shortcuts; the grid preview is a dialog and registers the action keys and Find action on the `overlay` surface instead. The workspace and the grid always register f, g and k and their Shift variants: they apply the action placed there, and on an empty key they do nothing, so Cove's Filters and fullscreen on f, its `g …` go-to chords and play/pause on k never fire on review pages while the page takes keys (Space, the **Filters** button and the player's fullscreen button still work). Other empty keys are not registered; Cove binds none of them on these pages. Each binding acts on the stroke Cove resolved, through the latest key map, so a stroke landing while Cove still holds an older list of bindings cannot reach another key's action. Cove does not filter key repeat for keys without an action definition, so the handlers ignore repeated keydowns: a held key applies its action once, and its repeats are still claimed so they do not reach Cove's own shortcut for the same key. Shift plus a key applies and stays in the single-item workspace only; the grid and its preview move on as before, and their Find action offers no Shift+Enter. Find action ignores the auto-repeat of a key held down since before it opened, so a held `-` opens it once and types nothing into its search; a key pressed again inside it types, and repeats, as usual. The workspace releases its keys while the tag editor, the editor drawer, Find action or a filter dialog is open, and while no item is shown; the grid releases them while Find action, the preview, the editor drawer (and its discard confirmation), or the New review or Delete… dialog is open, and while its queue is empty or failed. During a write or a load both keep them and ignore them, so a quick f, g or k never falls through to Cove between items. Cove itself skips text fields and, while any dialog is in the page, every surface below its overlays. Escape, Space, Enter and the arrow keys of the grid, and the preview's own keys, stay with the extension's handlers.

## Query and navigation

The URL carries the complete effective query using native `q`, `filters`, `sort`, `direction`, `sorts`, `perPage`, `page`, `seed`, and `searchMode` conventions. `performerScope` contains target mode, selected performers, performer profile criteria, and occurrence-tag conditions; these remain distinct from scene conditions in `filters`. `performer` narrows an occurrence queue and its batches to one performer chosen from the performer ranking; it is navigation state that saving never writes into the review, and changing the performer scope drops it. `startFrom` records traversal direction. Multi-column `sorts` uses the host's comma-separated `key:direction` format.

A bare review link reads the saved review and serializes its defaults. A link with query state never merges hidden saved criteria back in. Explicit `{}` scene filters and empty search remain empty. Changing queue criteria shows **Queue differs from the saved review** with **Save to review** and **Reset** on the header's chip row, in the workspace, the card grid and tag reviews. Reset replaces the URL with current saved defaults; save writes the effective queue criteria directly to the review, except queue tag bins, which no save ever writes (see Card grid and preview): with only bins pressed there is nothing to save, and the note offers **Reset** alone. **Single** | **Grid** keeps the saved criteria and the temporary query apart in both directions: the view switched to gets the saved review and reads the temporary query from the URL, so the note, **Save to review** and **Reset** carry on there, and Reset returns to the saved criteria. Saving the review, from the chip row or the editor, keeps the visit's layout; only a saved change of the review's own layout ends the header's switch. Ordinary changes replace browser history; browser navigation restores URL state. Switching reviews starts from defaults unless the destination has explicit query state.

New reviews start from the end. Existing explicit direction is honored, and an explicit URL page takes precedence over the default starting page. Scenes traverse toward the configured end; matching performers in each scene stay together. Skip performs no mutation and creates no exclusion, outcome, or completion record. The single-item workspace (video reviews in the Single video layout, audio and occurrence reviews) neither reads nor writes progress. Video reviews in the Grid layout and tag reviews do: they resume at the saved page and focused card with the saved card view and size, and write them back as the review moves on, but never while the queue differs from the saved review (see storage-and-verification.md).

Each successful tag save refreshes the loaded scene page, removing occurrences that no longer match and updating the scene count. A scene stays until its last matching performer has been tagged. Apply and stay keeps the current item open for inspection even if it leaves the queue. At forward boundaries the current page is reconciled for scenes shifted into it; reverse traversal proceeds to the preceding page. Reconciliation waits for the host query cache after writes, clamps invalid pages, and avoids choosing the just-traversed loaded items again. Revisiting or refreshing a page creates a fresh cursor. The native toolbar in the header shows the matching range and total, with a compact pager in its byline: previous, page / pages (its number opens a go-to field) and next. The queue rail beside the player has no pagination of its own and does not repeat counts or direction. No matches and reaching the end in the current direction have distinct messages.

## Card grid and preview

Video reviews in the Grid layout and tag reviews share the workspace's header: the host toolbar with the queue's one pager in its byline (no pagination rows above or below the cards), **Single** | **Grid** (video reviews; transient), **Cards** | **Wall** (**Cards** | **List** for tags) instead of Cove's own view buttons, Cove's card size control, and **More**. Below 1600 px the grid hides the toolbar's range text so the row stays single. The page fits the window: only the cards scroll, with room kept at their edges for the focus ring, and the action bar is sticky at the bottom of that scroll area over a fade of the cards, after the last row when the cards run out; a card brought into view clears it (scroll padding from its measured height). Below 900 px the page scrolls and the bar sticks to the window's bottom. Queue tag bins sit in the chip row as "On this page" toggle chips: a bin adds an exact-tag AND condition around the current criteria, the pressed state is read back from the filter (so it survives the URL), and lifting the last bin restores the saved criteria and direction. Bins narrow the visit only and are never saved: **Save to review** and the editor's **Save review** peel them off down to the saved filter, or to the criteria they were pressed on, and store that; afterwards the bins stay pressed, and the queue differs from the saved review by them alone. The single-item workspace shows no bin chips, but a bin carried over from the grid in the URL is treated the same way.

The action bar replaces the resizable actions sidebar and its stored width: the target ("N selected", "Applies to the focused video/tag", or "Nothing to apply to") over **Select all** (adds every card on the page; Ctrl/⌘A still toggles) and **Clear** (Esc), a tile per keyed action (key cap and label, the effect as its description and, on hover or focus, just above the bar), **Find action** ("N more" for the actions without a key), and hints or permission notes. The tiles take one line per keyboard row that holds actions (q…å, a…ä, z…b), in key order, so the rows read as on the pad; a line wraps within itself when it does not fit, and Find action closes the last line. When the tiles would take fewer rows under the summary than beside it, or as many while every keyboard row then fits on one line, the summary and hints take a line of their own. Blocked-key reasons and completion messages appear above the bar. Tiles pause without fading while an action or load runs, and a thin line along the bar's top edge shows it.

The preview is a dialog over the grid with previous/next (N/M), the video title and what actions apply to, **Selected**, the video in a new tab, and close; the player is 16:9 as large as fits, a hint line lists the keys, and the same action bar sits at the foot (grid and preview actions always move on). A pointer click on one of the preview's own buttons or links returns focus to the dialog (a keyboard-pressed button keeps it; the player's controls, portalled menus and Find action are left alone), and when a focused control is disabled by a running action or the last video and the browser drops focus to the page, the preview takes it back at the next frame; so Space, the arrows (volume on ↑/↓), `,`/`.`, N/M and Enter/Esc keep working. The preview stacks above Cove's navbar and modals and the page's own menus and drawer, but below Cove's portals, so the player's **Playback options** menu on a narrow window, Cove's chord hint and conflict toast, and hover previews open over it.

## Tag-group reviews

Tag-group reviews use the card grid and action bar above ("Applies to the focused tag"), with focused-item keyboard navigation, the same action keys, Find action and Ctrl+A (⌘A) select-all as video grids, group assignment or clearing, and account-scoped progress. Their existing workflow is separate from the filter-driven video and occurrence workspace. The review catalog and immutable review entity types are unchanged.

## Edit a review

**Edit review** opens the review's editor as a drawer over the right-hand column, in the single-item workspace and the card grid alike. The header's toolbar, **Scope**, the chip row and the queue stay live beside it as the draft's preview: their criteria, the performer scope of occurrence reviews included, are the draft's, and **Save review** stores them with the rest (meanwhile the chip row says **Previewing the draft**). The review's actions pause while the drawer is open: their keys are released, the pad or the action bar is dimmed and says so, **Batch…** is disabled, and the grid opens no preview. The drawer is a non-modal dialog, so Cove holds back its own page, list and player shortcuts too. Its tabs are **Review** (name, description, **Review direction**, and **Performer flags** in occurrence reviews; the entity type stays fixed), **Appearance** for reviews with a card grid (video reviews: the **Single video** or **Grid** layout the review opens in, which the header's switch overrides only for the visit, the grid's **Cards** | **Wall**, **Select every card when a page opens**, **Card details** and **Tags on cards**, and **Queue tag bins**; tag reviews: **Cards** | **List** and select-all), **Actions**, and **Tag choices** in legacy occurrence reviews that have them. The footer notes **Unsaved changes** beside **Cancel** and **Save review**, measured against the saved review with the queue's criteria as Save would store them: criteria already changed before the drawer opened (a search, filters, the direction) count from the start, and the note then reads **Unsaved changes, including the queue's criteria**; queue tag bins never count, as Save leaves them out. **Cancel** discards the draft and restores the queue, the shown item or the grid's selection, and the URL from before editing, temporary criteria included, and saves nothing. **Close editor** and **Esc** do the same at once while nothing differs from the saved review; with unsaved changes they first ask **Discard unsaved changes?** in a small modal dialog on the page, whose **Keep editing** (focused, and what Esc there means) hands focus back to where Close or Esc was pressed, and whose **Discard** does what **Cancel** does. The browser's Back asks nothing: leaving the review for the list discards the drawer's unsaved changes. The drawer is 720 px wide, 600 px between 1400 and 1699 px window width so more of the player stays in view, and below 900 px it sits in the page above the review. A failed save leaves the draft open for correction or retry, and a draft that cannot be saved says why and opens the tab, and the action, that needs completing.

The **Actions** tab lists the actions as compact rows in review order: a drag handle, the key, the label, what the action changes (**+** adds, **−** removes, assessments in words), a note when something is missing, then **Duplicate**, **Delete** and expand. One action at a time opens in full, with its **Button label** and ordered steps, each an operation, its tags and a remove button, and **Add step**; a tag review's action has its effect instead. **Add action** adds an empty action at the end and opens it, **Find an action** narrows the rows by label, and dragging a handle, or **Alt**+**↑**/**↓** on it, reorders the full list; steps reorder the same way. The key is a button that opens the key picker, a small keyboard map (rows q…å, a…ä, z…b, with n and m shown but not offered) in which each key shows the action that holds it, with a pin when it is pinned there, or nothing. Choosing a key pins the action to it; the action that held that key takes the chooser's pinned key, a swap, or turns Auto when the chooser had no pin, in which case the Auto actions may shift (any other action still pinned to a key that changes hands turns Auto too). **Auto** (the default) takes the next free key, and **No key** leaves the action to Find action. The picker is a small dialog: the arrow keys move between the keys and the two choices, Home and End go to a row's ends, Enter or a click chooses, Tab goes round the map's key, **Auto** and **No key**, and Esc or a press outside closes it; focus then returns to the key. Keys pinned in the row show a small pin, an action whose pinned key an earlier action also holds says so (for example "W is pinned twice") until a key is chosen for it, and the paused pad or bar shows the draft's placement while the drawer is open. A duplicated action starts on Auto (a copy of an action without a key stays without), and actions added from parent tags start on Auto.

**Add from parent tags…** in the Actions tab lists the direct children of the chosen parent tags, most used first: by media tags in video and audio reviews, and by occurrence tags, one aggregate count per child that stops at the first failure, in occurrence reviews. Each ticked child becomes one ordinary action after the existing actions, and adding waits until every chosen parent has loaded. Children an action already adds or marks present start unticked, and a child of several chosen parents is listed under the first and names the others. **Only one per video, audio, or performer** adds a removal of the parent's tree to the actions for that parent's children, including a shared child listed under another parent. Nothing links the actions to their parents afterwards; running the command again lists the children as they are then.

## Reviews list

The page without a review is the reviews list, at most 1240 px wide and centred, scrolling with the page: a header with **Import**, **Export all** and **New review**, the page's notices, a line with the number of reviews, where they are kept (the account, the account read-only, or this browser only) and **Sort by** (**Name** or **Matching items**) with its direction, then a table. Each row shows the kind's icon (labelled for assistive technology), the name with the description under it, the **Type** and the matching count, and ends in a menu (**Actions for** the review). Counts load review by review with the review's own queue criteria; an import or a deletion counts only the reviews without a count (new ones, and ones whose count failed), and coming back from a review counts them all again. Sorting by count puts the reviews still counting, or without a count, last; ties and the name order use natural, case-insensitive order. The sort (field and direction) is remembered per browser in local storage (`data-quality.reviews-sort.v1`, apart from the reviews); without readable storage the list sorts by name, ascending, and a choice that cannot be stored lasts while the page stays open. Below 760 px the **Type** column is left out.

The name is a link to the review's URL: a plain click opens the review in place, while a Ctrl, Shift or middle click opens it in a new tab or window, as for any link. A review opened from the list (its name, **Edit**, **Duplicate**, or **New review**) gets a browser history entry of its own, so the browser's Back returns to the list with that review's row focused, and Forward opens it again; everything a review then changes in the URL (its queue criteria, another review opened through **Duplicate**) replaces that entry. The row menu holds **Edit**, which opens the review in its own layout with the editor drawer once its queue has loaded, **Duplicate**, **Export** and **Delete…**; it opens upwards when the window has no room below. The open review's **More** menu holds **Edit review**, **Duplicate**, **Export**, **Delete…** and **All reviews**. Back on the list through **All reviews** (the header's back button or the **More** menu), its heading takes focus. **All reviews** from a review opened from the list goes back to the list's history entry, as the browser's Back does, once however often it is pressed before the list shows (a reload of the review keeps that); a review opened any other way (its own link, a new tab) turns its entry into the list's. Deleting the open review leaves for the list the same way. Back or Forward to the entry of a review deleted meanwhile shows the list under the list's URL, and the browser's Back and Forward leave the last view's notice behind. While a duplicate saves, the open review's way back, **Edit review** and layout switch wait; if the browser's Back or Forward moves the page meanwhile, it stays there and says the copy was saved instead of opening it.

**New review** opens a modal dialog with the kind, the name and the description; **Create & configure** (or Enter) saves the review and opens it with the drawer, a missing name is reported and focused, a failed save keeps the dialog and its draft, which **Export draft** can keep, and Cancel, close or Esc give focus back to what opened the dialog. **Duplicate** asks nothing: it saves a copy of the saved review (an open review's temporary queue criteria stay out) under a new id, named "<name> copy", or "<name> copy 2", "copy 3" and so on when a review already has that name (ignoring case; a copy's copy numbers on, so duplicating "X copy" gives "X copy 2"), and opens it with the drawer, where it can be renamed; a failed duplicate says why under the page's header, and focus stays on the menu it came from. **Delete…** asks in Cove's own confirmation dialog. A deletion from the list moves focus to the review in the deleted one's place, and one from an open review returns to the list's heading; a failed deletion closes the dialog, gives focus back to the menu it came from and says why under the page's header. While any of these dialogs is open the review's keys wait, and while an import, a duplicate or a deletion saves, the list offers no other change. What an import or a deletion did is announced through a live region that stays in the page.

**Export** downloads one review as a review file named after it, **Export all** every saved review in one file: a JSON array of saved reviews. **Import** reads a review file (at most 2 MB) with the same validation as the stored configuration and adds, in one save, the reviews whose ids the list does not hold; listed reviews stay as they are, the status says how many were added and kept, and a refused file names the reason and changes nothing. Without saved-filter write permission **New review**, **Import**, **Edit**, **Duplicate** and **Delete…** are unavailable while both exports remain.

## Apply to all matching occurrences

**Batch…** opens a modal dialog in three steps, **Answers**, **Preview** and **Run**, with a stepper marking the current one. **Answers** lists the configured occurrence tag actions (assessments are answered one occurrence at a time and are not offered) with their keys and effects; the selection starts empty for every batch, and the chosen answers combine, in review order, into one ordered action with one preview, run, and undo. The step also names the batch's scope (performers, occurrence condition with its tags, subtags, hidden confirmed absences, search, and the host's scene filter and performer criteria chips), the focused performer's existing answers per condition category with a Mixed badge, and, for a flagged performer, the warning to check the earliest and latest items or narrow the batch by date. **Preview all matches** moves to **Preview** and loads all matching appearances across every scene page; an unchanged choice keeps its preview when the user goes back and forth. The preview uses the effective URL query, independently of the visible page and traversal order, and matches occurrence conditions with the same subtag setting as the queue. It shows the answers to apply, the scope chips, the performer's existing answers, and counts of matching occurrences (and their scenes), occurrences that will change, occurrences already correct, and occurrences with a different answer; selecting a count lists those occurrences with links for inspection and the planned change of each. Replacing is explicit: occurrences with a different answer default to **Keep their answer**, and **Replace it** replaces it. Conflicts come from net removals in the ordered action, including removal-tree descendants resolved during preview. Each answer's removal trees spare that answer's own tags, as when it is applied alone. Existing correct answers require no writes. When the condition looks for missing tags and includes subtags, each condition tag with its subtree is also a category: an answer is added only where its category holds no answer yet, and an answer's own tags never count as a different answer. An occurrence whose category holds a different answer keeps it and is counted among those with a different answer, and other categories are still filled; replacing replaces that answer instead. Two chosen answers adding to one category are refused before any occurrence is read; the refusal stays in view, back on **Answers** too, until the answers change. Previewing the same answers again cannot help, so after a refusal the preview's primary button is **Change answers**, which returns to **Answers**; a preview that failed for another reason, or was cancelled, offers **Preview again**. The preview shows the date range of the matching items with links to the earliest and latest, which a flagged performer's warning repeats with their titles. Legacy choice-only reviews have no configured actions, so their batch control stays disabled.

**Apply to N occurrences** moves to **Run**. The run freezes target pairs before writes and processes at most five occurrences at once; a progress bar counts processed occurrences: a run counts the whole batch, as the results do, and a retry or an undo counts the occurrences it goes through. A fresh read checks affected tag values and application identities; changed answers are skipped, removed performer links fail, and unrelated tags and partners are preserved. Final action deltas are applied through existing occurrence APIs and verified after writing. These APIs do not provide an atomic compare-and-swap, so concurrent changes between the final read and write remain a limitation.

Results count changed, unchanged, skipped, failed, and remaining occurrences, list the reasons for skips and failures, each with **Show them** for the occurrences behind it, and list the occurrences behind a count when it is selected; a list whose count runs out closes. Cancellation lets in-flight writes settle and keeps remaining items available to **Continue**. **Retry failed** attempts only failed items with known current state, and completes the plan made at preview, so a partly written replacement finishes instead of stopping at the partial state. If a write cannot be verified, inspect the linked occurrence and create a fresh preview; do not blindly retry. **Undo batch** uses the recorded changes, including verified partial writes, says how many it restored, and retains conflicts or incomplete undo operations for inspection and another undo. The modal locks normal review edits and shortcuts, and stays open while anything runs, even when the browser closes it on a second Esc. Its tag badges keep Cove's colours and group dots but show no image preview on hover: the modal sits in the browser's top layer, above the body where Cove opens that preview, which would stay hidden under it. Closing the modal after a write refreshes the queue and discards the results and their undo; **New batch** discards them at once and starts over at **Answers**. Neither asks for confirmation, so undo is available only while the modal stays open on that batch. Keep the browser page open while running.

## Performer ranking and focus

Occurrence reviews switch the queue sidebar between **Scenes** and **Performers**. **Performers** ranks the performers in the review's performer scope by matching items, using the same search, scene filters, occurrence condition, and subtag setting as the queue, one count per performer through the host's aggregate query. Performers are counted in descending order of their total items; a performer's matching items never exceed their total, so counting stops once the next total is below the last place shown, and those places are exact. When fewer performers than the places shown have matches, every performer with any item is counted. A snapshot shown while counts are still in flight is never continued. A changed search, filter, or condition reuses the performers already loaded for the same performer scope and counts again; **Refresh** reloads them, picking up changed totals. **Show more performers** continues from where counting stopped. Counts include occurrences that the queue hides in the browser as confirmed absent when the condition has several tags.

Choosing a performer focuses the queue and batches on that performer and switches back to the scene list; the focus shows as a chip under the header, whose **Show all performers** removes it. The focus does not show the save and reset controls, because it is not a queue criterion. While focused, **Existing answers** summarizes the performer's answers across all of their items for each condition category, plus other tags the review's actions add, and marks categories holding more than one answer. A saved occurrence recounts its performer in the ranking; closing a focused batch recounts the focused performer; closing an unfocused batch discards the ranking so it is counted again when shown. A write while the ranking is still counting discards it and counts again. Performer flags name profile tags; flagged performers are marked in the ranking, on the focus chip and in the item column, and a focused, flagged performer's batch dialog asks to check the earliest and latest items or narrow the batch by date.
